# PrimusDB v1.3.2-alpha Release Notes

**Release Date:** 2026-08-04

> **Note**: This release notes page describes the TUI/IDE workspaces that were
> **removed from the build** shortly after this release. The TUI is no longer
> compiled or available in the current `v1.3.2-alpha` codebase; use the CLI/REPL
> or REST API instead. System database, API, and CLI sections below remain
> current.

## Overview

v1.3.2-alpha continues PrimusDB's evolution toward a robust terminal-native database platform with significant improvements to the system database (internal metadata & config persistence), terminal TUI/IDE workspaces, and system configuration management.

**Highlights of this update (2026-08-04):**
- **Namespace Switch**: `:namespace use <name>` command or `u` key to switch active namespace; shown with `◆` marker.
- **Query Export**: `:export query <file>` to save results; `Ctrl+S` shortcut in QueryConsole.
- **Settings Overhaul**: Edit endpoint (`e`), auth token (`t`), cycle theme (`h`), toggle safe mode (`s`).
- **Theme Engine**: `ThemePalette` system with dark/light/high-contrast palettes applied to sidebar & status bar.
- **TUI Config Persistence**: Endpoint URL now persisted across sessions.
- **6 new tests** for themes, settings, namespace switch, export query, and render validation.

## New Features

### System Database Enhancements
- **TUI Config Persistence**: TUI settings (mouse, theme, refresh interval, safe mode) are now persisted to the system database and survive server restarts (`SystemDatabase::set_tui_config` / `get_tui_config`).
- **Runtime Config Snapshot**: The server's `PrimusDBConfig` is automatically persisted on startup for export/backup integration (`SystemDatabase::set_runtime_config` / `get_runtime_config`).
- **System DB Export API**: New `GET /api/v1/system/export` endpoint returns a JSON bundle of config entries, catalog entries, audit events, and server info.
- **System DB Import API**: New `POST /api/v1/system/import` endpoint accepts a JSON bundle to merge config entries into the system database.
- **TUI Config API**: New `POST /api/v1/system/tui-config` endpoint for remotely saving TUI configuration.
- **Server Info Persistence**: On startup, the server now records its version, node ID, cluster mode, engine types, and start time to the system database.
- **Inline Architecture Documentation**: All system database modules (`mod.rs`, `config_store.rs`, `catalog.rs`, `audit.rs`, `migrations.rs`) now include ASCII architecture diagrams and module-level docs.

### API & Server
- `PrimusDB::init_system_db()` now persists runtime config snapshot and server info metadata on startup.
- Three new REST endpoints for system database operations.

### TUI IDE Workspaces
- All 5 new NavSection workspaces from v1.3.1-alpha (ConfigurationStudio, TableExplorer, ReportBuilder, Notebook, RAGWorkspace) are now fully documented.
- TUI Settings section displays connection status and allows editing refresh interval, mouse toggle.
- TUI config persistence means user preferences survive restarts.

### TUI Shell (v1.3.2b)
- **Namespace Switch**: `:namespace use <name>` command or `u` keybinding in Namespaces section to switch the active namespace. Active namespace shown with `◆` (cyan, bold) in namespace list and in status bar.
- **Query Export**: `:export query <file>` saves last query result to a file on disk. `Ctrl+S` shortcut opens command palette with pre-filled `:export query` prefix.
- **Settings Overhaul**: 
  - Press `e` to edit server endpoint URL.
  - Press `t` to set or clear auth token (shown masked as `****`).
  - Press `h` to cycle themes (default → dark → light → high-contrast).
  - Press `s` to toggle safe mode for destructive actions.
- **Theme Engine**: New `ThemePalette` system with 3 named palettes (`dark`, `light`, `high-contrast`). Theme affects sidebar, status bar, and empty state colors. Accessible via CLI `--theme` flag or Settings `h` key.
- **TuiConfig extension**: `endpoint` field persisted to system database for session continuity.
- **6 new unit tests** covering theme resolution, settings modes, command parsing, and render correctness. Total TUI tests: 58.

## Fixed
- Version string in `src/lib.rs` updated from `1.3.1-alpha` to `1.3.2-alpha`.
- Borrow-after-move fix in `api.rs` for `fetch_system_db_import` and `fetch_save_tui_config`.

## Changed
- `SystemDatabase::set_server_info()` now calls `db.flush()` for durability.
- Server startup sequence improved with richer metadata persistence.

## Known Limitations
- Federation is experimental.
- TLS not yet configurable via CLI.
- Windows not tested.
- TUI settings are persisted but not yet hot-reloaded from system DB on change; a TUI restart is required.
- The system DB import API accepts config bundles but does not overwrite existing entries; it appends.

## Testing
- All existing tests pass (387 unit + 23 integration).
- New system database functionality tested via existing 29 system module tests.
- Manual verification of:
  - `cargo check --workspace` — zero errors
  - `cargo build --workspace` — builds successfully
  - System DB export/import round-trip via API
  - TUI config persistence across simulated restarts

## Upgrade Notes
- No breaking changes to existing APIs.
- The system database is auto-initialized on server startup; existing `{data_dir}/system/` directories are reused.
- TUI config is automatically persisted when using the Settings section to modify preferences.
